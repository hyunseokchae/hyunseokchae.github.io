U04 · Predictive Maintenance / IoT ML

게이트·단말기 예지보전 AI/ML 적용 프로세스

Predictive Maintenance — AFC 장비 IoT 데이터 기반 고장 사전 예측 및 정비 최적화

AFC 게이트·단말기·충전기 등 현장 장비의 IoT 센서 로그·오류 코드·정비 이력을 분석하여 고장 발생 전 잔여 수명(RUL)과 고장 확률을 예측한다. 규칙 기반 임계치 탐지에서 Random Forest · XGBoost · LSTM 앙상블 모델로 진화하여 계획 정비 전환율 70%+, 다운타임 30~50% 감소를 목표로 하며, 예측 결과는 유지보수 스케줄링 시스템에 자동 연계된다.

업무 문제 정의

Business Problem Definition
현재 문제점
  • 사후 정비 중심: 고장 발생 후 출동 수리 — 다운타임이 1~4시간에 달하는 경우 빈발
  • 계획 없는 예방 정비: 일정 주기로 전수 점검하나 실제 고장과 무관한 낭비 발생
  • 오류 코드 미활용: 장비 로그에 사전 경고 신호(오류 코드 증가)가 있으나 실시간 분석 부재
  • 부품 재고 비효율: 고장 예측 부재로 부품 과잉 재고 또는 긴급 조달 비용 발생
  • 현장 인력 낭비: 우선순위 없이 전체 장비 점검 → 정비 인력 비효율 배치
AI 적용 목표
  • 고장 사전 예측: 7일 이내 고장 가능성 예측으로 계획 정비 전환
  • 잔여 수명(RUL) 추정: 장비별 예상 수명 시점 제공으로 교체 계획 최적화
  • 우선순위 정비 알림: 고위험 장비 자동 우선순위화 → 정비팀 파견 최적화
  • 부품 수요 예측: 고장 예측 기반 부품 조달 계획 자동화
  • 다운타임 절감: 다운타임 30~50% 감소 및 MTTR 단축

탐색적 데이터 분석 (EDA)

Exploratory Data Analysis
고장 전조 패턴 분석
  • 오류 코드 누적 증가: 고장 전 7~14일간 특정 오류 코드 발생 빈도가 3~5배 증가하는 패턴 확인
  • 응답 지연 증가: 태그 처리 응답시간이 고장 전 72시간부터 통계적으로 유의하게 증가
  • 거부율 증가: 고장 직전 48시간 동안 태그 거부(Read Error) 비율 급상승
  • 센서 진동 이상: 모터 구동 진동값이 정상 범위(σ±2) 초과 후 평균 3.2일 내 고장 발생
장비 유형별 패턴 분석
  • 게이트 (플랩): 모터 과부하 오류 → 플랩 잠김 → 물리적 고장 순서 패턴
  • 단말기: RF 통신 오류 증가 → Hang 재부팅 반복 → 완전 오프라인
  • 충전기 (현금 모듈): 지폐 걸림 이벤트 누적 → 롤러 마모 → 모듈 교체 필요
  • 계절성: 우기·고온 다습 시 전자 부품 오류 30% 증가, 겨울 저온 시 기구 부품 마모 가속
MTBF / MTTR 분석
MTBF (평균 고장 간격)
게이트 평균 MTBF 85일, 단말기 120일, 충전기 60일 수준. 장비 노후화(3년+) 시 MTBF가 50% 이하로 단축
MTTR (평균 복구 시간)
평균 MTTR 2.4시간. 역 위치 원격성·부품 재고·기술자 가용성에 따라 30분~8시간까지 편차 큼
고장 집중 시간대
피크 시간(07~09시, 17~20시) 직후 30분에 고장 신고 집중. 부하 누적 후 약한 부품부터 순차 이탈

Baseline 모델

Baseline Model
규칙 기반 임계치 탐지
Rule-based Baseline IF err_cnt_critical_7d >= 5 → ALERT OR days_since_last_pm >= 90 → SCHEDULE PM OR reject_rate_7d >= 0.05 → ALERT OR repair_count_1y >= 3 → HIGH RISK → Baseline Recall ~55%, Precision ~42%
Baseline 성능 분석
  • 재현율 55%: 실제 고장의 45%는 사전 경보 없이 발생 → 개선 필요
  • 정밀도 42%: 경보의 58%가 실제로 고장 없이 종료 → 정비 인력 낭비
  • 임계치 한계: 장비 유형·노후도·환경 조건 차이를 반영하지 못함
  • ML 개선 목표: Recall 80%+, F1 0.70+ 달성으로 전체 정비 효율 2배 이상 향상

고장 발생 비율 약 2~5%. SMOTE로 소수 클래스 오버샘플링 + class_weight 조정을 병행하여 Recall 우선 모델 학습. 임계치(threshold)를 0.3~0.4로 낮춰 고장 탐지 민감도 증가
Train / Validation 분할
시계열 특성 유지를 위해 무작위 분할 금지. 최근 3개월을 Validation, 이전 데이터를 Train으로 설정. 장비 유형별로 별도 모델 학습하여 유형 간 패턴 차이 반영
