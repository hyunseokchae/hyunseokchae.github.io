보고타 LLM 민원 챗봇 PoC 추진 계획서 (한국 TSC 내부 검증)

TransMilenio FAQ · Tarifa · Rutas 문서 기반 RAG 검증 및 다국어 챗봇 검증 — Korea TSC Internal R&D

본 계획서는 한국 TSC 내부 개발·검증 환경에서 진행하는 3개월 기술 검증(PoC)으로, TransMilenio 공개 FAQ·tarifa(요금)·rutas(노선) 문서를 지식베이스로 구축하여 고객이 요금·환승·카드·노선 조회를 질문했을 때 문서 기반으로 정확한 답변을 제공할 수 있는지를 검증하는 것이 핵심 목적이다. 검증은 두 축으로 진행한다: ① 문서 기반 RAG 검증 — 검색된 문서가 올바른지, 답변이 문서에 근거하는지(Context Faithfulness), ② 다국어 챗봇 검증 — 스페인어 질문 처리(실서비스 경로)와 한국어↔스페인어 번역 파이프라인(TSC 내부 평가 경로)의 품질. 검증 인력은 5명 내외로 운영하며, 결과는 향후 보고타 본사업 제안 시 기술 수준·인력·일정·예산 산정 근거로 활용한다.

PoC 사전 준비사항

Pre-PoC Prerequisites
본 PoC는 한국 TSC 내부 5명 내외가 진행하는 기술 검증 활동이며 실서비스에 적용하지 않는다. 스페인어 네이티브 검수자는 별도 두지 않고, LLM 번역 결과(한국어)를 내부에서 평가하는 방식으로 운영 범위를 축소한다. 착수 전 다음 항목들을 확보해야 일정·품질·산출물의 신뢰도가 보장된다.

PoC 범위 정의

Scope Definition — In / Out
⚠️ 본 PoC는 한국 TSC 내부 기술 검증이 목적이며, 실서비스 운영·실고객 파일럿·보고타 현지 인프라 구축은 포함하지 않는다. 검증 결과는 향후 보고타 본사업 제안 시 적용 범위·기술 수준·예산 산정의 근거 자료로 활용된다.
IN-SCOPE — PoC 대상 기능
✔ 웹 채팅 UI (스페인어)
  • PC/모바일 웹 브라우저 기반 스페인어 챗봇 인터페이스
  • 비회원 접속 가능 (별도 로그인 불필요)
  • 텍스트 입력 및 답변 표시, agente 이관 버튼
✔ FAQ 자동응답 (RAG 기반 · ES)
  • 4대 카테고리 — 요금(Tarifa)·환승(Integración)·카드(TuLlave)·노선(Rutas)
  • TransMilenio FAQ + 약관/정책 문서 기반 벡터 검색 답변
  • 신뢰도 낮은 답변 시 "확인 필요(verificar)" 처리
✔ Intent 분류 (스페인어)
  • 스페인어 민원 카테고리 자동 분류 (6~8개 클래스)
  • 분류 결과 기반 응답 경로 분기
  • LLM 프롬프트 기반 또는 경량 분류 모델
✔ 상담원(agente) 이관 판단 (기본)
  • 민감 키워드 감지 시 이관 안내 (룰 기반)
  • Intent 신뢰도 임계값 미달 시 이관
  • 이관 요청 수동 버튼 제공
✔ 기본 모니터링 대시보드
  • 자동응답률, 이관율, 카테고리별 문의 건수
  • 답변 피드백 (좋아요/싫어요) 집계
OUT-OF-SCOPE — PoC 제외 항목
✗ Agent 개발
  • 자율 판단·다단계 실행 AI Agent 개발은 본 PoC 범위 외 — RAG 챗봇 + 룰 기반 이관으로 한정
✗ 실서비스 운영 / 실고객 노출
  • 본 PoC는 한국 TSC 내부 검증용으로 실고객 대상 서비스 노출은 일체 제외
✗ 보고타 현지 인프라 구축
  • 현지 서버·네트워크·운영 인력 구성은 본사업 단계에서 별도 진행
✗ 실고객 파일럿 (TransMilenio 고객)
  • 외부 사용자 노출 없이 TSC 내부 5명 내외로 시뮬레이션 검증만 수행
✗ 스페인어 네이티브 검수
  • 별도 검수자 미운영 — LLM 번역으로 한국어 변환 후 내부 평가 (자연스러움 평가는 본 PoC 제외)
✗ 음성봇 (STT/TTS)
  • 콜센터 음성 연동 — 구현 복잡도 및 인프라 비용 높음
✗ 개인화 (TuLlave 잔액·거래 API 연동)
  • Recaudo Bogotá 결제/카드 시스템 API 연동 — 보안 검토 기간 필요
✗ 본인인증 연동 (cédula)
  • 금전 환불·개인 계정 조회 — 별도 인증 시스템 연동 필요
✗ 멀티채널 (WhatsApp, 앱, 이메일)
  • WhatsApp·앱 SDK·이메일 연동 — 채널별 별도 개발 필요
✗ 다국어 확장 (영어 등)
  • PoC는 스페인어 단일 언어 — 다국어는 본사업에서 검토
✗ 자동 재학습 파이프라인
  • MLOps 인프라 — PoC 후 본사업에서 구축
✗ 실시간 운행 정보 연동 (llegadas)
  • 버스 도착·운행 API 실시간 연동 — PoC 범위 초과

기능 상세 명세

Functional Specification
기능 1 — FAQ 자동응답 (RAG 기반)
항목내용
설명고객 질문을 벡터 검색으로 유사 문서를 찾아 LLM이 자연어로 응답 생성
입력고객 텍스트 입력 (최대 500자)
처리Query 임베딩 → 벡터 DB 검색 → 상위 3개 문서 추출 → LLM 프롬프트 조합 → 답변 생성
출력자연어 답변 + 출처 문서 표시 (FAQ 항목명 또는 약관 조항)
예외유사도 점수 0.6 미만 → "담당자 연결" 안내로 자동 전환
성능 목표응답시간 5초 이내, 답변 정확도 80%+
기능 2 — Intent 분류
항목내용
설명스페인어 고객 발화를 미리 정의된 민원 카테고리로 자동 분류
분류 클래스충전(Recarga) / 요금·정산(Tarifa) / 잔액(Saldo) / 카드 분실(Tarjeta) / 노선 안내(Rutas) / 불편 신고(PQR) / 기타(이관)
구현 방식LLM Few-shot 프롬프트 분류 (PoC) → 향후 스페인어 BERT(BETO) 파인튜닝 검토
출력카테고리 레이블 + 신뢰도 점수 (0.0~1.0)
예외신뢰도 0.7 미만 → "기타" 처리 후 이관 판단 로직으로 전달
성능 목표분류 정확도 85%+
기능 3 — 상담원 이관 판단 (룰 기반)
이관 조건설명처리
민감 키워드 감지환불(reembolso)·보상·소송(demanda)·위협 관련 키워드 포함즉시 이관 안내 + agente 알림
Intent 신뢰도 낮음분류 신뢰도 0.7 미만이관 안내 메시지 표시
개인정보 요구 감지cédula·카드번호·계좌번호 입력 시도입력 차단 + 이관 안내
반복 문의동일 세션 내 3회 이상 유사 질문이관 권유 메시지
고객 수동 요청"agente 연결(hablar con un agente)" 버튼 클릭즉시 이관 처리
기능 4 — Guardrail (안전장치)
유형내용처리
입력 필터욕설·스팸·비정상 입력 감지응답 거부 + 안내 메시지
출력 필터LLM 생성 답변 내 개인정보·부적절 내용마스킹 또는 응답 차단
정책 외 안내 방지RAG 출처 외 정보로 답변 생성 시출처 기반 답변만 허용 (Source Grounding)
허위 안내 방지Hallucination 의심 답변신뢰도 낮으면 "확인 필요" 처리
범위 외 질문업무 외 주제 (정치·종교 등)응답 거부 메시지 반환
기능 5 — 웹 챗봇 UI 요구사항
기능상세우선순위
채팅 인터페이스말풍선 형태 대화 UI, 타이핑 중 로딩 표시필수
빠른 선택 버튼자주 묻는 유형 버튼 (Recarga·Tarifa·Saldo·Tarjeta·Rutas)필수
상담원 연결 버튼언제든 클릭 시 이관 처리필수
답변 피드백👍 / 👎 버튼으로 답변 품질 수집필수
출처 표시답변 근거 문서 표시 (FAQ 항목, 약관 조항)권장
대화 초기화새 대화 시작 버튼권장
반응형 디자인PC·모바일 웹 대응권장

본 PoC는 실고객·실데이터 미사용 원칙으로, 모든 입력 데이터는 PM·AI 엔지니어가 한국어로 작성한 후 LLM 번역으로 변환한 가상 민원·가상 cédula·가상 카드번호로 한정한다. 내부 검증 인력(5명 내외)의 대화 로그는 한국 TSC 내부 시스템에만 저장하고, PoC 종료 후 30일 이내 파기한다. 향후 보고타 본사업 적용 시 콜롬비아 개인정보보호법(Ley 1581 de 2012, habeas data) 준수 요건을 본 PoC 결과 보고서에 사전 정리하여 첨부한다.
